# **Exposicions temàtiques**

## Git i GitHub como Plataforma de control de versiones:

###  **GitHub:**
   - GitHub es una plataforma basada en la nube donde puedes almacenar, compartir y trabajar junto con otros usuarios para escribir código.
   Por lo tanto GitHub  es la forma visual que se tiene para compartir el código que subamos al repositorio, de esta manera las demás personas pueden acceder al código, copiarlo, modificarlo y sugerir cambios en él.


### **Git:**
   - Git por otro lado es la parte funcional, que nos da la capacidad de interactuar con los repositorios con los diversos comandos que tiene.


### **Funciones de Git:**
- Permite la creación de proyectos además de tener su historial de modificaciones.
    Pueden ser tanto privadas como públicas, por lo tanto permite la modificación de los proyectos de diferentes personas a la vez.
    Permite volver a una versión anterior funcional en caso de error.
    Otra función útil es el uso de ramas en caso de que el proyecto necesite integrar diversas características hechas por equipos diferentes, los equipos pueden crear ramas independientes para trabajar en su parte y una vez acaban pueden juntar a la rama principal con la función “merge” y así al final se junta el trabajo de todos los equipos en la rama principal.

    En resumen tenemos varias funciones:

- **Clone:** Esta función sirve para clonar un “proyecto ya existente” a tu repositorio.
- **Init:** Init seria para  poder inicializar un repositorio nuevo.
- **Log:** Log permite revisar los cambios como un historial.
- **Pull:** Sincronizar el repositorio de tu equipo con el que está en github.
- **Commit:** La función commit esta para guardar los cambios en la rama, para hacerlo primero tienes que añadirlos a ella, para eso existe el (add o el .add). En cada commit se recomienda poner una pequeña descripción de lo que has hecho, ya que al final del día puedes hacer muchos commits y si al final quieres retroceder a una versión anterior tienes que saber a cual.
- **Branch:**(Rama) Es una característica fundamental que permite trabajar en diferentes versiones de un proyecto de manera simultánea.
- **Check out:** Se utiliza para cambiar entre ramas, restaurar archivos y realizar otras operaciones relacionadas con la gestión de ramas y el estado del repositorio.
-**Push:** Se utiliza para enviar los cambios confirmados en tu repositorio local a un repositorio remoto. Este es un paso crucial en el flujo de trabajo de Git, ya que permite que otros colaboradores vean y accedan a tus cambios.
